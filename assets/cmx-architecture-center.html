04

How HTML connects to Python

The browser sends a request. FastAPI validates it. Python performs the work and returns structured data.

core example
HTML form > JavaScript fetch() > FastAPI endpoint > Python function > database or AI > JSON response > page update
Connect a URL form to a Python endpoint

An operator enters a website address. JavaScript sends it to the backend. FastAPI validates the input before Python handles it.

HTML 
<form id="url-form">
  <input id="target-url" type="url" required>
  <button type="submit">Inspect URL</button>
</form>
<pre id="result"></pre>
Browser JavaScript 
document.querySelector("#url-form").addEventListener("submit", async (event) => {
  event.preventDefault();

  const url = document.querySelector("#target-url").value;
  const response = await fetch("/api/url/analyze", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ url })
  });

  const result = await response.json();
  document.querySelector("#result").textContent = JSON.stringify(result, null, 2);
});
FastAPI and Python 
from fastapi import FastAPI
from pydantic import BaseModel, HttpUrl

app = FastAPI()

class UrlRequest(BaseModel):
    url: HttpUrl

@app.post("/api/url/analyze")
def analyze_url(request: UrlRequest):
    return {
        "url": str(request.url),
        "status": "accepted",
        "next_step": "Run approved inspection checks"
    }

HTML collects the value. JavaScript transports it. FastAPI validates it. Python processes it. JSON carries the result back to the page.

Where PostgreSQL enters the flow

Use a database when information must persist, belong to a user or project, be searched later, or support history and audit records.

browser request
      |
FastAPI permission check
      |
Python business logic
      |
PostgreSQL read or write
      |
JSON response
Why secrets cannot live in HTML or JavaScript

Anything delivered to the browser can be inspected. API keys, database passwords and private tokens stay on the server in environment variables or a secret manager.

05

Practical build examples

Projects that fit the direction of db.cmxchat.com.

blueprints

URL intelligence inspector

Inspect redirects, status codes, headers, metadata and technologies.

  1. User submits a URL.
  2. FastAPI validates the address and permission.
  3. Python performs allowed checks.
  4. Results return as JSON.
  5. The page renders findings.

Evidence report generator

Turn saved investigation records into a consistent sourced report.

  1. User selects a case.
  2. Python retrieves approved records.
  3. AI organizes verified findings.
  4. Sources remain attached.
  5. An operator reviews the output.

Private knowledge assistant

Ask questions across approved CMX documents and research.

  1. User submits a question.
  2. Permissions limit accessible collections.
  3. Python retrieves relevant passages.
  4. AI answers from those passages.
  5. The page displays citations.

Metadata processing queue

Upload files, extract metadata server-side and preserve a processing record.

  1. User uploads an approved file.
  2. FastAPI checks type and size.
  3. Python extracts metadata.
  4. PostgreSQL stores status.
  5. The page shows completion.

Website brief builder

Combine crawl findings, content observations and operator notes.

  1. User enters a domain.
  2. Python gathers approved data.
  3. Rules identify issues.
  4. AI drafts from verified findings.
  5. An operator approves the brief.

Controlled AI code assistant

Translate a natural-language request into a reviewed GitHub change.

  1. User describes the change.
  2. The assistant receives limited context.
  3. Changes go to a branch.
  4. Tests and staging run.
  5. Production requires approval.
06

AI layer

AI receives approved context through Python and returns structured output under access controls.

controlled intelligence

Good AI jobs

  • Summarization
  • Classification
  • Drafting from records
  • Entity extraction
  • Search assistance
  • Natural-language controls

Python controls

  • Select context
  • Mask sensitive data
  • Call model APIs
  • Require structured output
  • Store audit details
  • Reject unsupported actions

MCP role

  • Expose narrow tools
  • Connect approved services
  • Separate read and write access
  • Keep actions observable
  • Limit permissions
  • Support controlled automation

Learning tracks

Open the topic that matches the feature you are trying to build.

practical learning
I want an HTML button to run Python

Learn forms, browser events, fetch(), JSON, a FastAPI POST endpoint, Pydantic validation and rendering returned results.

I want information to save after I close the page

Learn database tables, identifiers, create/read/update/delete operations, migrations, permissions and how FastAPI talks to PostgreSQL.

I want AI to read approved documents

Learn file ingestion, text extraction, retrieval, source permissions, model prompts, citations and evaluation.

I want natural language to change the website

Learn scoped repository access, branch creation, patches, automated tests, staging previews, review and production approval.

I want a page to process uploads

Learn multipart forms, file-size rules, safe file names, isolated processing, job progress and cleanup.

I want the useful parts of Linux

Focus on inspecting services, viewing logs, checking disk space, restarting an approved container and confirming health.

09

Feature decision guide

Choose the smallest layer that can perform the job correctly.

scope control

HTML + CSS

Content, layouts, navigation and reference pages with no processing or saved state.

Add JavaScript

Browser interactions, local calculations, filtering and calls to backend APIs.

Add FastAPI + Python

Protected logic, external service calls, validation and server-side processing.

Add PostgreSQL

Persistent records, users, projects, search, history and audit information.
