Why React if HTML, CSS and JavaScript already work?

React is not a mysterious fourth web language. It is a JavaScript library for organizing interactive frontend interfaces into reusable pieces. The browser still ends up displaying normal interface elements styled with CSS and controlled with JavaScript behavior.

The useful mental model

React helps you build and control the frontend using reusable pieces.

Those reusable pieces are called components. A component can represent something small like a button or something richer like a complete Weather card.

HTML structure+CSS appearance+JS behavior→React components

Compare the idea

Plain markup can repeat the same shape again and again

That is totally valid for simple pages. The pain shows up when a large app has many similar interactive pieces that need the same behavior and structure.

Database basics

What does PostgreSQL actually look like?

At your current level, picture organized tables with rows and columns. IDs let records connect to each other. The database can store those relationships, while Python decides when and why they should be read or changed.

users

One row per example user.

Click the relationship button and watch the matching IDs light up. This is the beginning of how relational databases connect records.

↳Keep this distinction: PostgreSQL does not “create the morning briefing” by itself. Backend logic can gather/process/create the briefing, then PostgreSQL can store the resulting records.

Developer-soup translator

Search the word that broke the explanation

Technical conversations get way easier when you stop letting one unexplained noun poison the next five sentences.

Frontend

The part of the application running in the browser that the user sees and interacts with.

Backend

Private server-side code that owns application logic, rules, protected processing, API endpoints, and database access.

React

A JavaScript library used to build interactive frontend interfaces from reusable pieces.

Component

A reusable piece of frontend UI, such as a WeatherCard, button, form, or briefing section.

TypeScript

JavaScript with added type information that helps tools catch mistakes and describe expected data shapes.

API

A defined way for software to ask another piece of software for data or actions.

Endpoint

One specific API method + path that handles a kind of backend request, such as GET /briefings.

HTTP request

The structured message traveling from frontend to backend.

HTTP response

The structured answer traveling from backend back to frontend.

JSON

A common text format for structured data sent between software layers.

Python

The programming language used to write the backend logic in this environment.

FastAPI

A Python web framework that makes it easier to define backend API endpoints, validate data, and return responses.

PostgreSQL

A relational database used to store durable structured application data.

Table

An organized database structure made of columns and rows.

Row

One record in a database table, such as one user or one briefing.

ID

A value used to uniquely identify a record and help connect related records.

Authentication

Proving who a user is.

Authorization

Deciding what an authenticated user is allowed to see or do.

Password hash

A one-way representation used to verify a password without storing the readable password itself.

Token

A form of authentication proof that can be checked on later requests.

Session

A continuing logged-in state that lets a server recognize a browser across requests.

State

Information the frontend is currently keeping track of, such as selected Space or loaded data.

Props

Data passed into a React component so the same component can display different information.

Route

A mapping between a location/request and the code that should handle it. The word is used in both frontend and backend contexts.

OpenAPI

A machine-readable description of an API. Later, this can help generate frontend client code from the backend API.

Generated API client

Frontend code produced from the API description so the React app can call known backend endpoints with known data shapes.

Migration

A recorded change to the database structure, such as adding a new column or table.

Docker

A container system used to package and run application services in a defined environment.

localhost

A hostname that points back to your own computer during local development.

Port

A numbered network doorway used by a running service, such as a local frontend or backend server.

No matching term. That might mean the glossary needs another word added.

The sentence we are building toward

You should be able to explain the app in your own words, not recite mine

The target is not “I recognize React, FastAPI and PostgreSQL.” The target is that when somebody changes an endpoint, adds a database field, or builds a new Spaces component, you can roughly place that change in the architecture and ask what happens next.

Try saying this without looking back:

“I click something in the React frontend. If it needs the backend, the frontend sends an HTTP request to an API endpoint. FastAPI routes that request to Python logic. Python can read or change PostgreSQL. Then the backend responds and React updates what I see.”
