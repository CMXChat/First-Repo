Backend world

Turn “the backend did something” into five separate jobs

HTTP moves a request. An endpoint is the method + path door. FastAPI matches that door and helps validate web input. Python contains the backend instructions. A JSON response carries structured result data back to the frontend.

Request body / JSON

Structured data can travel with a request

POST and PATCH requests often carry data. JSON is a common text format for structured fields such as title, visibility or settings. FastAPI can validate whether incoming data has the expected shape.

Data world

Tables store records; keys connect them; migrations change the structure

Start concrete: rows are records, columns describe fields, a primary key identifies a row, a foreign key links to another record, and a query asks the database to read or change data. Models and ORMs are code-side ways to describe/work with those structures.

A migration is a recorded database-structure change. The environment spec expects risky schema changes to be reviewable and backed up appropriately.

Later vocabulary: SQL is the database query language. An ORM maps code objects/models to database structures. Exact ORM choice is still an open environment decision; Alembic is listed as a strong migration candidate if SQLAlchemy-based models are chosen.

Identity + security world

Authentication and authorization are two different gates

Login proves identity. Passwords should be verified against hashes, not stored as readable text. A session or token can carry continuing login proof. Then authorization checks whether that known user may access a specific resource.

Authentication

Who are you?

Email/password → backend finds account → safely verifies password against stored hash → session/token or equivalent proof supports later requests.

Password hash = one-way representation used for verification without storing the readable password.

Authorization

Are you allowed to do this?

An authenticated user can still be denied access to somebody else’s private Space. Protected endpoints need both identity and permission rules.

401 commonly means identity/authentication is missing or invalid. 403 commonly means identity is known but permission is denied.

Permission gate

Try identity and permission separately

gate 2Permission
resultPrivate briefing

401 · identity not proven yet.

Later security awareness includes cookies, bearer tokens, refresh tokens, session expiration, CORS, rate limiting, HTTPS, security headers and secret handling. These belong in deeper security lessons after the basic gates are solid.

Generated API client world

The backend can describe itself so the frontend gets matching client code

This is a real environment-specific idea: FastAPI exposes an OpenAPI description. The project can generate TypeScript functions/types from it. React then calls that generated client. The generated folder should not be hand-edited.

1FastAPI endpoints
2OpenAPI description
3Generate client
4TypeScript client
5React calls it

FastAPI endpoints exist on the backend.

Important rule: do not manually edit frontend/src/client/. It is generated code.
Known regeneration command:
cd frontend
bun run generate-client
OpenAPI is a machine-readable API description. Detailed schema mechanics can wait. The useful mental model is backend contract → generated frontend helper code.

Local runtime world

localhost is your machine; ports are numbered doors to running services

A full-stack app can have multiple services running on the same computer. Environment variables carry configuration. Secrets stay outside source code. Docker can package repeatable runtime boundaries and Compose can coordinate multiple services.

AI authority world

Useful access needs hard edges

The environment is intentionally AI-assisted, but generated work should not become magic or unlimited authority. Routine project work can move fast. Larger blast-radius actions pause. Some behaviors stay blocked.

allowed

Routine work

Read approved files, create routes/services/schemas/tests, run allowlisted development commands, explain errors/diffs and prepare Git changes.

review

Human checkpoint

Add/upgrade dependencies, change schema/migrations, broad architecture changes, important deletion, staging/production deploys and credential/provider actions.

blocked

Never silently

Hardcode secrets, access unrelated projects, rewrite protected Git history, bypass tests/production approval or run arbitrary destructive shell commands.

Tool + decision world

Know what is confirmed, what is proposed and what is still undecided

This prevents a common learning mistake: hearing a tool name in a setup and assuming the project has permanently standardized on it. The environment spec itself distinguishes locked direction, strong candidates and open decisions.

Confirmed direction

locked
  • Python is the primary backend language.
  • FastAPI is the primary application template.
  • GitHub remains source control/source of truth.
  • Secrets stay out of source.
  • AI works inside guardrails.

Strong candidates

proposed
  • PostgreSQL as default relational database.
  • Docker + Compose for repeatable services.
  • Alembic if SQLAlchemy-based models are selected.
  • pytest for Python tests.
  • Uvicorn as likely ASGI server.

Still open

decide
  • Python/FastAPI versions.
  • Dependency manager.
  • ORM/model pattern.
  • Linting + type-checking defaults.
  • Hosting/deployment target.

Recovery world

Failures should have boring, evidence-first paths

The environment spec explicitly treats recovery as part of the design. Git handles code history. Database backups/migration state protect data. Logs and health checks tell you what a running service or release actually did.

code

AI changed too much

Inspect the diff and last known-good state before adding more changes.

database

Migration went bad

Protect writes, inspect revision/state, downgrade only when safe or restore backup.

runtime

Server will not start

Read the first meaningful error and verify configuration/services before redesigning.

deploy

Release failed

Identify revision, inspect health/logs, rollback and reproduce in staging.
