How an HTML page connects to Python

The browser never runs the protected Python function directly. JavaScript sends a request to a FastAPI endpoint, Python performs the work, and the page receives a structured response.

Core lesson
HTML form → JavaScript fetch() → FastAPI endpoint → Python function → optional database or AI → JSON response → page update
Practical example: connect a URL form to Python

An operator enters a website address in an existing HTML page. JavaScript reads the form and sends the address to the backend.

HTML
<form id="url-form">
  <input id="target-url" type="url" required>
  <button type="submit">Inspect URL</button>
</form>
<pre id="result"></pre>
Browser JavaScript
document.querySelector("#url-form").addEventListener("submit", async (event) => {
  event.preventDefault();

  const url = document.querySelector("#target-url").value;
  const response = await fetch("/api/url/analyze", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ url })
  });

  const result = await response.json();
  document.querySelector("#result").textContent = JSON.stringify(result, null, 2);
});
FastAPI and Python
from fastapi import FastAPI
from pydantic import BaseModel, HttpUrl

app = FastAPI()

class UrlRequest(BaseModel):
    url: HttpUrl

@app.post("/api/url/analyze")
def analyze_url(request: UrlRequest):
    return {
        "url": str(request.url),
        "status": "accepted",
        "next_step": "Run approved inspection checks"
    }

What happened: HTML collected the value, JavaScript transported it, FastAPI validated it, Python processed it, and JSON carried the result back to the page.

Where PostgreSQL enters the flow

A database is needed when information must persist, be searched later, belong to a user or project, or form part of an audit history. A temporary URL result may not need storage. A saved investigation, report, project, user permission, or route history usually does.

Browser request
      ↓
FastAPI permission check
      ↓
Python business logic
      ↓
PostgreSQL read or write
      ↓
JSON response to browser
Why secrets never belong in HTML or JavaScript

Anything delivered to the browser can be inspected. API keys, database passwords and private tokens must stay on the server in environment variables or a secret manager. The browser calls CMX. CMX calls the outside service with the protected credential.

Where AI fits

AI is an optional reasoning layer. It should receive approved context through Python, return structured output, and remain behind access controls and human review where accuracy matters.

Intelligence layer

Good AI jobs

  • Summarization
  • Classification
  • Drafting from verified records
  • Entity and relationship extraction
  • Search assistance
  • Natural-language tool control

Python's role

  • Choose approved context
  • Remove or mask sensitive data
  • Call the model API
  • Require structured output
  • Store audit details
  • Reject unsupported actions

MCP's possible role

  • Expose narrowly defined tools
  • Connect GitHub or approved services
  • Limit available actions
  • Keep tool use observable
  • Separate read and write permissions
  • Support controlled automation

Learning tracks

Open only the track relevant to the thing you are building. The page is organized around outcomes, not a generic programming syllabus.

Optional depth
I want an HTML button to run Python

Learn forms, browser events, fetch(), JSON, a FastAPI POST endpoint, Pydantic validation and rendering the returned result.

I want information to save after I close the page

Learn database tables, identifiers, create/read/update/delete operations, migrations, permissions and how FastAPI talks to PostgreSQL.

I want AI to read my approved documents

Learn file ingestion, text extraction, chunking, retrieval, source permissions, model prompts, citations and evaluation.

I want ChatGPT-style language to change the website

Learn scoped repository access, branch creation, patch generation, automated tests, staging previews, review and production approval. Natural language can initiate a controlled workflow, but it should not bypass it.

I want a page to process uploads

Learn multipart forms, file-size rules, safe file names, isolated processing, background jobs, progress states and cleanup.

I want to understand Linux without becoming a server administrator

Focus on the commands needed to inspect services, view logs, check disk space, restart an approved container and confirm health. Routine deployment should be automated.

What does this feature need?

A quick guide for deciding whether a new idea needs only frontend work or the full backend platform.

Decision guide

HTML + CSS

Use for content, layout, navigation and visual reference pages with no processing or saved state.

Add JavaScript

Use for browser interactions, local calculations, filtering, file inspection supported safely in-browser and calling APIs.

Add FastAPI + Python

Use for protected logic, external service calls, server-side processing, validation and operations the browser should not control.

Add PostgreSQL

Use when information must persist, belong to users or projects, be searched later, or support history and audit records.

Architecture is the agreement. Code is the implementation.
