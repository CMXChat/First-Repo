How the code works

What is actually running under the page

The visible page is one layer. Server code checks requests and rules. The database keeps information that must survive refreshes, logins and restarts.

CODE HOMEGitHubWhere the project code and change history live.
WORKBENCHCodespacesA ready-made development computer in the browser. Docker helps keep the setup repeatable.
WHAT YOU SEEFrontendHTML, CSS and JavaScript today, with React and TypeScript in the protected app stack.
SERVER CODEPython + FastAPIReceives requests, checks identity and rules, then decides what server work may happen.
LONG-TERM MEMORYPostgreSQLThe database keeps users, content, policy, Incidents and future Runtime records.
WHEN YOU TAP A BUTTON
1You tap something in the browser
2The frontend sends a secure HTTPS request
3FastAPI checks who you are and what the request may do
4PostgreSQL reads or saves the durable data
5The answer comes back and the screen updates
DockerKeeps the development setup repeatable.AlembicKeeps database changes in order.OpenAPI clientHelps the frontend call backend endpoints correctly.TestsCatch broken behavior before it spreads.
See the technical version
Browser → HTTPS/JSON → FastAPI domain services → PostgreSQL → JSON response → frontend

The frontend never talks directly to PostgreSQL. The backend owns business rules, permissions and database access.

The Lab lets us try a screen or workflow quickly. Once it feels right, we write down the rules, build the real database and server behavior, then move the accepted experience into the protected product.
