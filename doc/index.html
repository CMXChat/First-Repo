How the code works

What is actually running under the page

The visible page is only one layer. Code on the server checks requests and rules, and the database keeps the information that must survive refreshes, logins and restarts.

CODE HOMEGitHubWhere the project code and change history live.
WORKBENCHCodespacesA ready-made development computer in the browser. Docker helps keep the setup repeatable.
WHAT YOU SEEFrontendHTML, CSS and JavaScript today, with React and TypeScript in the protected app stack.
SERVER CODEPython + FastAPIReceives requests, checks identity and rules, then decides what server work may happen.
LONG-TERM MEMORYPostgreSQLThe database keeps users, content, policy, Incidents and future Runtime records.
ONE SIMPLE REQUEST
You tap something in the browser
The frontend sends a secure HTTPS request
FastAPI checks who you are and what the request is allowed to do
PostgreSQL reads or saves the durable data
The answer comes back and the screen updates
DockerKeeps the development setup repeatable.AlembicKeeps database changes in order.OpenAPI clientHelps the frontend call backend endpoints correctly.TestsCatch broken behavior before it spreads.

How ideas become real

Design it quickly, then give it a real backend

The Lab lets us try a screen or workflow quickly. Once it feels right, we write down the rules, build the real database and server behavior, then move the accepted experience into the protected product.

Give the frontend a protected APIThe browser and future AI tools call the same server rules.
Move it into /checkin/The accepted screen now uses real server-backed data.

Where Continuum can go

The foundation can keep growing as technology gets better

New AI models, apps, communication channels and data sources can plug into the same information, rules and permission model. The build order keeps each new ability tied to real server state and clear history.

The basic idea stays simple: Continuum keeps the useful world around the AI, including people, records, source history, rules, tools, timing, conversations and results. Better models can use that same world as they become more capable.
