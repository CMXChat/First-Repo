Afterlife

The Dead Man Switch

Afterlife uses Continuum for continuity. You choose the timer. If you stop checking in long enough, the live Check In core records the trigger. Future Runtime can follow the authority and steps prepared in advance.

72 + 24 is today's configuration. You choose these periods.The current live setup uses a 72-hour check-in window plus 24 hours of grace. Both values can be changed, and each policy change keeps its own history.
AUTHORITY CAN HAVE A CONTINUITY PLAN TOOBeing unreachable does not require the system to invent permission.

A policy can define what happens when normal approval is available and what alternate authority applies when it is not.

NORMAL PATHDirect approval is available
Action proposed→Approval→Execute
FALLBACK PATHDirect approval cannot be obtained
Check fallback policy→Alternate authority or safe action→Wait or prohibit when required
Fallback is prepared authority. Continuum should never treat silence, absence or urgency as permission by itself. Any alternate action must come from a policy established beforehand.

Architecture

Two views of the same product

The technical stack explains how requests move through code. The Continuum architecture explains how knowledge, authority, intelligence and capability fit together as the product grows.

CODE HOMEGitHubWhere the project code and change history live.
WORKBENCHCodespacesA ready-made development computer in the browser. Docker helps keep the setup repeatable.
WHAT YOU SEEFrontendHTML, CSS and JavaScript today, with React and TypeScript in the protected app stack.
SERVER CODEPython + FastAPIReceives requests, checks identity and policy, then decides what server work may happen.
DURABLE STATEPostgreSQLThe database keeps users, content, policy, incidents, authority and future Runtime records.

Database access goes through the backend. The backend owns business rules, authority, permissions and PostgreSQL access.

CONTINUUM ARCHITECTUREThe model is one replaceable part inside a larger operating layer.

The durable product is the path that connects sources, knowledge, state, policy, capability and results across time.

SourcesMessages, files, apps, sensors, APIs and direct input.
KnowledgePeople, relationships, records, history and meaning.
StateWhat is happening now, what changed and what is pending.
ReasoningCurrent AI model or future intelligence chosen for the job.
Policy + AuthorityAllowed scope, approvals, fallback and prohibitions.
Tools + RuntimeAvailable actions, waits, retries and long-running coordination.
Results + AuditOutcome, evidence, updated state and execution history.

New capability can be inserted into this architecture without redefining the core rules that govern it.
