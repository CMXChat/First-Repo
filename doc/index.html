Continuum in one minute

One loop connects information to what happens next

Continuum receives approved information, keeps where it came from and how current it is, builds the context needed for a decision, then gives Automations or AI access to approved tools. Results can return to the same durable state and change the next briefing or action.

01Receive

Email, calendar, messages, files, finance, APIs, MCP, webhooks and direct updates can become inputs.

02Remember

Directory, Library, records, conversations, versions and source history stay attached to stable IDs.

03Reason

AI receives the smallest approved context needed for the task and uses typed tools through protected services.

04Act and update

Automations and future Runtime can communicate, wait, retry, coordinate, record results and update state.

The Dead Man Switch

Afterlife applies Continuum's timing, protected information, people, Automations, Connections and authority when the owner stops responding. The current switch core already runs against authoritative server time.

01 · CHECK INProtected check-inThe backend records authoritative server time.
02 · WINDOW72 elapsed hoursThe active production deadline is measured in UTC.
03 · GRACE24 elapsed hoursThe configured grace window follows the primary deadline.
04 · INCIDENTTriggeredA durable Incident can activate exact pre-authorized continuity rules.
05 · CONTINUEApproved workflowsFuture Runtime can communicate, release, coordinate and delegate within the published grant.

How it is programmed

A real browser, API and database stack with clear boundaries

The project is also a practical learning environment for how modern applications work. The browser handles the interface, FastAPI owns protected server behavior, PostgreSQL holds durable state, and migrations evolve the database deliberately.

SourceGitHubRepositories, commits, reviews and source of truth.
DevelopmentCodespaces + Dev ContainerA repeatable environment with the expected tools and dependencies.
FrontendHTML, CSS, JavaScript + React / TypeScriptStatic prototypes today and a typed application frontend for protected product work.
BackendPython + FastAPIEndpoints and domain services validate requests, enforce rules and return JSON over HTTPS.
DatabasePostgreSQLDurable server-authoritative state for users, content, versions, policies, Automations and future Runtime.
DockerAlembic migrationsOpenAPI + generated clientTests + deployment gates
Programming principle: the frontend asks for work through protected APIs. Business rules live in reusable backend services. AI and later MCP adapters call those same typed services, so the product does not need a separate privileged path for machines.
